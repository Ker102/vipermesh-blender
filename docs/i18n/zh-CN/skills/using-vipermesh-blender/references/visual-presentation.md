# 视觉呈现

<a id="build-a-useful-feedback-loop"></a>
## 构建有用的反馈循环

使用预览回答具体问题：构图、相对比例、朝向、可见性、材质可读性、接触和灯光方向。避免反复生成不会改变决策的截图。

对于参考重建，先比较最大的视觉锚点，再把时间花在小细节上。后续轮次可以按预期相机中的显著性优先处理对象。

<a id="camera"></a>
## 相机

焦距、相机高度、透视和画面填充都是创意性且任务相关的。使用取景工具和相机检查来匹配请求的结果；不要强行套用通用室内、产品或电影 preset。

检查必需对象是否可见，以及重要剪影是否被意外裁切或隐藏。相机可能掩盖结构错误，因此视觉取景不能替代空间验证。

<a id="lighting"></a>
## 灯光

根据预期光源、情绪、材质响应和渲染引擎选择灯光。Studio preset 是孤立资产的有用起点，而自定义灯光和 world environments 可能更适合有明确窗户、灯具、户外条件或风格化方向的场景。

判断曝光、颜色分离、阴影可读性，以及明亮区域是否抹掉材质颜色。数值能量范围是起点，而不是场景无关规则。

<a id="acceptance"></a>
## 验收

检查最终渲染工件，而不仅是工具成功响应。如果仍有可见问题，请进行聚焦修复并重新渲染，而不是重建无关场景元素。

`inspect_render_artifact` 检查图像完整性，不检查画面是否符合 brief。使用客户端的 image/viewer 能力打开图像。如果客户端无法查看，请说明视觉质量仍未验证。

对于每个必需对象或编辑，将证据与用户意图进行比较：存在性和比例、功能朝向、接触或附着、间隙、可见性和材质可读性。当主相机隐藏可疑关系时，拍摄诊断性侧视或俯视图。基于 bounds 的支撑报告可能漏掉中空支撑、旋转部件、把手和局部网格碰撞。请结合实际几何和陈述意图解释它们，而不是把通过报告当作完整验收。修复后重新检查受影响关系。
